# 私家写手 · 视觉与产品评审报告

- **评审对象**：`index.html` + `styles.css` + `app.js`（纯前端高保真原型，深色墨感）
- **评审视口**：1440×900、1280×800（DPR 2，Chromium / Playwright）
- **覆盖页面**：作品库、写作台、故事大纲、人物设定（人物 / 伏笔两态）、剧本工坊（正文 / 分镜板）、新建向导（步骤 1 / 方案 2）、连续性检查、搜索空结果、导出弹窗
- **方法**：逐屏截图 + DOM 度量（字号、坐标、滚动容器、对比度）+ 上下文切换行为验证
- **局限**：仅桌面两种宽度，未测 1920 / 平板；动效时长与滚动性能未量化；对比度按 WCAG 2.1 相对亮度计算

---

## 总分 **7.5 / 10**

**一句话结论**：宋体 + 墨色 + 朱砂的视觉语言已经是专业水准，叙事文案也懂作者；但 302 条字号声明里有 195 条 ≤10.5px、首屏（两种视口）都看不到"我的作品"、从短篇点"大纲"会静默跳到另一本书——它现在是一份"有质感的设计稿"，还不是一个"撑得住演示的写作工作台"。

---

## 亮点

1. **字体系统有辨识度**：`--serif: Songti SC` 用在 `h1` 与 `.editor`（17.5px / 2.08 行高 / 0.35px 字距），中文长文在深底上的呼吸感对了，首字缩进 2em、段距 0.55em 也符合中文出版习惯。
2. **色彩克制成体系**：墨底 `#0a0c10` 三层递进 + 朱砂 `#d4634c` 只做强调（主按钮、当前章、AI 标记），玉色 / 金色只用于状态语义，没有"多彩 SaaS"的廉价感。
3. **"AI 记忆"被设计成了可见对象**：`.memory-card`（38.2k / 128k 预算条 + 记忆 chip）、`.ghost-block`（虚线建议块 + 接受 / 换一个 / 忽略）、`连续性检查` 三张问题卡——这是长篇作者真正会买单的东西，比"聊天框"高级。
4. **大纲页是全场最强的一屏**：情绪张力曲线 + 章节诊断 + 三幕卡片三件套，把"结构"这件事可视化了，`张力 8.6 / 访客身份悬念` 这类文案有产品洞察。
5. **剧本格式正确**：场景标题、动作、居中角色名、`（画外）`、`切至：`、右下页码的位置都符合剧本页习惯（页码被视口裁切另见 P1-5），`.script-page` 13.5px / 1.95 的纸面阅读感方向正确。
6. **作品库首屏（局部）有冲击力**：38px 衬线问候 + 书本封面 + 42% 进度环，情绪铺垫到位。

### P0-1 作品库首屏看不到"我的作品"

- **截图**：`shots-visual/01-library-1440.png`、`01-library-1280.png`

- **判断**：一个"作品库"首屏不含作品，演示时观众第一眼看到的是 4 个统计数字和一张大卡，这是定位偏差。
- **建议（可立即做，不重构）**：
  - `.stat-card` padding `15px 17px 14px` → `11px 14px`；`.stat-card__value` 30px → 24px；`.stat-card__foot` 9.5→11px：行高 124 → **≈92**（-32）。

  - `.lib-cols` `margin-top: 30px` → 22px；`.lib-head` `margin-bottom: 28px` → 20px（-16）。
  - 合计 **-134px** → `#projectGrid` 上移到 ≈643，首屏能看到约 200px 作品卡（封面 + 标题 + 进度条）。
  - **更彻底（推荐）**：统计条压成一条 56px 的"今日写作 · 连续 12 天 · 本周 56% · AI 采纳 78%"横条，把"继续写作"降级为第一张作品卡上的主按钮——首屏 = 问候 + 一行状态 + 3 张作品卡。

### P0-3 换作品后，点"大纲/设定"会静默跳到另一本书

- **行为实测**：打开《最后一班渡轮》（短篇，`tabs: [{studio:'正文'}]`）→ 点左轨"大纲" → 顶栏项目名变成 **《雾港来信》**，正文、左栏、页头全部换书，**没有任何提示或过渡**；再点"设定"同样。原因在 `app.js` `setView()`：`if ((view === 'outline' || view === 'codex') && state.project !== 'fog') state.project = 'fog'`。
- **为什么是 P0**：演示中一旦点开短篇/剧本演示，再点大纲，产品会显得"记不住当前作品"，这是长篇工作台最不能犯的错；而且短篇作者永远拿不到大纲与设定库。
- **建议**：
  1. 让短篇 / 剧本也拥有 `outline` / `codex`（`projects.ferry` 已有 `chapters` 数据，补一套三幕与人物即可），`tabs` 统一为 `正文 / 大纲 / 设定`；
  2. 若暂不补数据，则切换时必须给反馈：`.toast` 文案"已切换到《雾港来信》· 该作品暂无大纲"，同时左栏 `.panel-project` 做 200ms 高亮；
  3. 或者在 rail 的"大纲/设定"上做 `disabled` 态 + `title="《最后一班渡轮》还没有大纲 · 点击创建"`，并提供创建入口。

## 对产品功能的 3 条最重要建议

### 1. 作品库改造成"写作仪表盘"，首屏只回答一个问题：今天写哪一段

统计数字（今日 1,820 字 / 连续 12 天 / 本周 56% / AI 采纳 78%）对作者是**回顾性**信息，而作品是**行动对象**。建议首屏结构：一行 56px 状态条（今日字数 · 连更 · 本周目标）→ 3 张作品卡横向并排，第一张为"继续写作"大卡（封面 + 上次写到 + 续写按钮）→ 统计与今日目标下沉到右栏。这样 1440 与 1280 都不会出现"作品在折线以下"。

### 2. 建立"当前作品"的单一上下文，并让短篇/剧本共享同一套三件套

现在"当前作品"由 `state.project` 隐式决定，短篇只有"正文"tab，点大纲会被静默换成《雾港来信》。这套 IA 只对"长篇 = 雾港来信"成立，一旦演示短篇或剧本就散架。建议：`作品 → 正文 / 大纲 / 设定 / 剧本` 作为**同一项目内的四个工作区**（rail 只留作品库 + 当前项目，项目内切换交给左栏 segmented），短篇/剧本各自补最小可用的三幕与人物数据；切作品时用顶栏面包屑 + 淡入过渡明示。

### 3. AI 面板从"聊天记录"升级为"可审阅的稿纸"

右侧 360px 的空间，现在 60% 给对话气泡，最差异化的 `.ghost-block`（带虚线、带"按 Tab 接受"的行内建议）却埋在正文第 1,300px 处，首屏看不到。建议：**AI 面板主视图 = 3 条候选续写（每条带"采纳 / 更克制 / 展开记忆引用"）**，对话降级为次要 tab；把当前这条建议同时投射到正文末尾并保证首屏可见；每条建议显示"引用了 4 项记忆 · 38.2k tokens"，点开是 chip 明细——把"长篇记忆"这个卖点做成看得见的证据，而不是一个 8px 的配额数字。
