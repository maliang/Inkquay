# Inkquay 的 AI 主导创作流程

> 面向使用者。讲清楚新版「AI 先企划、你审核确认、AI 再逐章往下写」怎么用：每个阶段你能做什么、怎么给 AI 提意见、怎么确认、怎么暂停和恢复、旧作品怎么升级、出错时看到什么。
>
> 这一版是 **v1（流水线第一版）**，边界见最后一节。文档描述的是本仓当前工作树的行为，随代码一起走，不是发布承诺。

---

## 1 一句话看懂这次改了什么

以前是「AI 辅助编辑器」：新建作品得到一个**空白章节**，AI 藏在旁边的共笔面板里，得你自己想好设定和大纲再一句一句让它写。

现在是「AI 主导流水线」：你说一句灵感，AI 先把**设定**（世界观 / 环境 / 人物）和**故事大纲**写出来，你逐条改、逐条提意见，确认之后 AI 再给**章节计划**（几章、每章写什么、写多长），确认之后才开始**逐章写正文**。

| 环节 | 旧版 | 现在 |
| --- | --- | --- |
| 新建之后 | 空章节 + 共笔面板 | 作品立即保存，AI 在后台做企划，页面自己跳到「企划工作台」 |
| 设定 / 大纲 | 自己写，AI 只在共笔里帮你 | AI 先出一版，你可以逐条编辑、提意见重做、锁定、回看历史 |
| 章节计划 | 没有这个概念 | 章数 + 每章功能 / 大纲 / 字数区间，可批量分配、可整体确认 |
| 写正文 | 一章一章让它写 | 「开始连续写」自动往下推，随时可暂停 / 停止 / 单章重写 |
| 剧本 / 剧集 | 剧本工作台 | **不变**，仍走剧本工作台，不进 AI 流水线 |

关键变化是**每一步都要你点头**：AI 不会自己从「一句灵感」一路写完整本书，也不会在你没确认章节计划前动正文。

## 2 五个阶段一张表

「企划工作台」左侧是阶段轨道，按顺序解锁：

| 阶段 | 名称 | AI 产出什么 | 你要做的事 | 确认门槛 | 能否跳过 |
| --- | --- | --- | --- | --- | --- |
| P1 | 设定 | 世界观（题材、基调、核心冲突、规则）、环境（地名/场所，带类型）、人物（身份、动机、秘密） | 改内容、提意见重做、锁定、删掉多余的、补齐缺的 | 人物 ≥ 1、环境 ≥ 1、没有占位内容、世界观的核心规则不是空的 | 可以（全书只在这一阶段能跳过） |
| P2 | 故事大纲 | 若干「幕」，每幕下若干「节拍」（发生了什么、起什么作用） | 调整幕与节拍的顺序、重命名、合并删减、给某一幕提意见重做 | 幕 ≥ 3 且每幕有节拍；不足 3 幕需要你显式确认接受 | 不可以 |
| P3 | 章节计划 | 章数、每章的功能 / 大纲 / 出场人物 / 字数区间（最少 / 目标 / 最多） | 改章数与每章字数、用预设套档、按目标字数自动分配、处理总字数偏差 | 每章都有功能、大纲、合法字数区间；总字数与目标的偏差已处理 | 不可以 |
| P4 | 逐章写作 | 正文，一章接一章 | 开始 / 暂停 / 停止、重写单章、逐章审阅（通过 / 退回 / 人工通过 / 跳过） | 每章必须由你审阅，AI 不会自动给「通过」 | 不可以 |

短篇没有「章」，把 P3 / P4 的「章」换成「节拍」即可，其余完全相同（见第 8 节）。

## 3 新建：「创建并让 AI 企划」点下去之后到底发生什么

### 3.1 弹窗里先做一次配置预检

勾上「创建后让 AI 先做企划」后，弹窗底部会出现一行预检结果：

| 预检状态 | 你看到什么 | 能做什么 |
| --- | --- | --- |
| 检查中 | 「正在检查模型配置…」 | 等一下（通常不到 1 秒） |
| 可用 | 「✓ 将使用 {供应商} · {模型}」 | 直接点「创建并让 AI 企划」 |
| 不可用 | 「⚠ 还不能让 AI 企划：…」 | 「去设置里选模型」或「仍然创建（只能自己写）」——后者创建**不带企划**的空作品 |

预检不通过时**不会创建作品**，所以不会留下一个 AI 从没动过的空壳。

### 3.2 点下去之后的四种结果（都不会「没反应」）

| 结果 | 界面上可观察的现象 | 出路 |
| --- | --- | --- |
| 加载中 | 弹窗立即关闭，跳到 `/project/<id>/pipeline`；顶部任务条显示当前阶段名、已用时（每秒递增）和「取消」 | 可以离开：切页面、关窗口都不中断；回来还在跑 |
| 成功 | 任务条消失，阶段状态从「生成中」变「待确认」，左侧阶段轨道出现内容，右下角「下一步」按钮指向你要做的事 | 开始逐条审核 |
| 失败 | 阶段状态变「生成失败」，页面顶部出现错误卡：一句人话说明 + 「重试这一步」（可重试时才有） | 按错误卡提示修配置 / 重试，作品和已生成的内容都还在 |
| 取消 | 最多 5 秒内停住，任务条消失，错误卡显示「已取消」；AI 写了一半的内容不会入库 | 重新开始，或先去改设定 |

三条硬规则：

1. **作品在点击的瞬间就已经保存**，之后的企划是后台任务。所以「我点了没等它跑完就关掉」不会有任何损失。
2. **失败不会留下空壳**：要么干净地没有作品（预检拦截），要么作品在但阶段是「生成失败」且给得出原因。
3. **重试是幂等的**：创建请求带幂等键，连点两次也是同一本作品，不会出现两本。

### 3.3 哪些作品进流水线

| 类型 | 进流水线 | 说明 |
| --- | --- | --- |
| 长篇小说（10 万字以上） | ✅ | 章节口径 |
| 短篇小说（3,000–15,000 字） | ✅ | 节拍口径 |
| 电影剧本 | ❌ | 走剧本工作台，直接打开会进剧本页 |
| 剧集大纲 | ❌ | 同上 |

不勾「让 AI 先做企划」时，长篇 / 短篇仍按旧方式创建，你得到一个可以自己写的写作台（旧路径保留）。

## 4 P1 设定：世界观、环境、人物

**进入条件**：作品已创建（走了 AI 企划）或旧作品已升级到流水线。

页面分三块：世界观（1 条，含题材 / 基调 / 核心冲突 / 规则）、环境（按「城 / 村 / 机构 / 异境」分类的条目卡）、人物（条目卡）。每条卡右侧有操作：

| 操作 | 作用 | 备注 |
| --- | --- | --- |
| 编辑 | 直接改文字 | 改完保存；AI 再生成时会先提醒「这一条被你手改过」 |
| 重生成 | 让 AI 重写这一条 | 只重做这一条，其它不动 |
| 提意见 | 写一段话告诉 AI 你想怎么改，只重做这一条 | 意见太短会被拦下（「说清楚一点，AI 才知道往哪改」） |
| 历史 | 看这一条的每次改动（AI 初稿 / 按意见重做 / 整份重生成 / 你的修改 / 回滚 / 迁移） | 可以恢复到任意一版 |
| 锁定 | 锁住后任何批量重生成都不会覆盖它 | 已锁定的条目在覆盖确认清单里会被点名 |
| 删除 | 删掉这一条 | 锁定的要先解锁 |
| ↑ ↓ | 调整顺序（影响大纲生成的先后） | |

**意见的三档范围**（在页面级的「给 AI 提意见」抽屉里选）：

- 这一条：只重做被点的那一条。
- 这一块：重做环境或人物这一整块。
- 整个阶段：重做 P1 全部内容 —— 如果里面有手改或锁定的条目，会先弹「这会覆盖你手改过的内容」，要你点「确认覆盖并重排」才继续；手改的历史仍留在修订记录里可找回。

**确认门槛**：人物 ≥ 1、环境 ≥ 1、没有占位内容、世界观的核心规则不是空。达不到时「确认设定」按钮旁边的清单会逐条写缺什么（清单本身可点，点了定位到对应条目）。

**跳过**：P1 是唯一可以「跳过」的阶段（「跳过设定，我自己写？」）。跳过只表示这一阶段不阻塞下游，之后随时可以回来补。

**刷新 / 重启**：所有状态都在本地数据库里，刷新后回到同一阶段同一位置；任务被中断（App 被关掉或崩溃）会在顶部给「上次的生成被中断了……从断点继续」。

## 5 P2 故事大纲

**进入条件**：P1 已确认（或已跳过）。

AI 产出两层结构：**幕**（这一幕起什么作用：钩子 / 推进 / 转折 / 揭示 / 高潮 / 收束 / 缓冲）和幕下的**节拍**（发生了什么）。操作与 P1 相同（编辑 / 重生成 / 提意见 / 历史 / 锁定 / 删除 / 排序）。

- 跨幕拖动节拍：**v1 不支持**。调整顺序只支持「同一幕内重排」；想换幕请新建一条或在正文里处理，界面会明确写出这条限制，不会假装移动成功。
- 改了 P1 之后：P2 会被标成「上游有变更」，给你三个选项——保留现状 / 按上游重生成 / 先忽略。不会自动删你已经写好的大纲。

**确认门槛**：至少 3 幕且每幕有节拍；不足 3 幕时需要你显式确认接受这个结构。

## 6 P3 章节计划：几章、每章写什么、写多长

**进入条件**：P2 已确认。

这是整条流水线里最像「表格」的一步，也是决定后面 AI 写作质量的一步：

| 你能改的 | 规则 |
| --- | --- |
| 章数 | 长篇 3–200 章，短篇 3–40 节拍 |
| 每章功能 | 推进主线 / 揭示信息 / 关系变化 / 铺垫伏笔 / 回收伏笔 / 冲突升级 / 高潮 / 收束 / 过渡 |
| 每章大纲 | 一句话说清这章发生什么（也会作为写正文时的指令） |
| 每章字数区间 | 最少 ≥ 300、最多 ≤ 20,000，且必须 最少 ≤ 目标 ≤ 最多；默认 2,500 / 3,000 / 4,000 |
| 章节顺序 | 上下移动 |

批量工具：

- **字数档**：快 / 标准 / 厚重（短篇显示「极短 / 标准 / 舒展」），一键把每章区间套成一套预设。
- **按目标字数分配**：先给一份预览（每章会变成多少字），你确认后才应用。手改过的章不会被悄悄覆盖。
- **总字数偏差**：计划总字数与作品目标字数差超过 25% 时要你处理——要么确认接受这个偏差，要么回去调字数区间。

两条保护：

1. **减章不会静默删正文**：要删掉的范围内只要有一章已经有正文，就会被拦下并列出是哪几章（提示「已有正文的章不能通过减少章数删除，可以先只删空白章」）。
2. **计划未确认不能开写**：确认前「开始连续写」「重新开始」是禁用状态，按钮旁写着「先确认章节计划」。

**确认门槛**：每章都有功能、大纲、合法字数区间，且偏差已处理。

## 7 P4 逐章写作

**进入条件**：P3 已确认。

### 7.1 控制条

| 按钮 | 语义 |
| --- | --- |
| 开始连续写 | 从第一章（或第一处没写的章）开始，按章节计划一章接一章往下写 |
| 暂停 | **写完当前这一章**再停下（不会把半章丢在库里），之后可以「继续写作」 |
| 停止 | 立刻中断并**丢弃当前这一章**的未完成内容；停止后不能「继续」，只能重新开始 |
| 继续写作 | 从暂停处接着写 |
| 重新开始 | 从头重写（已有正文的章会先要确认） |
| 送去审阅 | 把写完的章送进审阅队列 |

控制条会显示当前状态（生成中 / 已暂停 / 已停止 / 已完成）、**正在写第几章**和已用时；出错的章会被单独标出来。

### 7.2 单章失败不打断整本

某一章因为限流、超时、内容被拦等失败，**不会**让整本停下来：其它章继续写，失败章在章节板里标红，你可以点「重试本X」（只重做这一章）或先跳过。全部章节都到了终态，这次写作才算「已完成」。

### 7.3 审阅

每章写完后是「待审阅」，四个动作（在写作台里）：

| 动作 | 结果 |
| --- | --- |
| 通过 | 这一章定稿（后续批量重生成不会动它） |
| 退回修改 | 标记「需修改」，并按你的意见重写这一章 |
| 人工通过 | 你手改过、不打算让 AI 再动的章，直接标定稿 |
| 跳过 | 这一章不写 |

版本：每次 AI 写、每次你重写，都会留一份快照；写作台里可以对比与回滚（回滚是「另存一版」，不会把历史抹掉）。

### 7.4 已知限制（v1，如实写）

- 章节行内的「立即写本章」按钮**没有**跟着「计划未确认」一起禁用；在计划未确认时点它，服务端会拒绝并给「请先确认章节计划」的提示。整条控制条是正确的，只有这个行内按钮漏了约束。
- 写作中途不能改章节数（服务端会拒：「正在生成，等它跑完或先取消再改章数」）。

## 8 短篇：没有「章」，只有「节拍」

短篇走的是**同一套阶段、同一套按钮**，只是换了计量单位：

| 长篇 | 短篇 |
| --- | --- |
| 章节计划 | 节拍计划 |
| 每章功能 / 大纲 / 字数 | 每个节拍的功能 / 大纲 / 字数 |
| 3–200 章 | 3–40 个节拍 |
| 逐章写作 | 逐节拍写作 |
| 章节板 / 章节行 | 节拍板 / 节拍行 |

界面上凡是出现「章」字的地方都会自动换成「节拍」，短篇作品里**不会**出现章节树（这是硬约束，测试里直接断言章节行数为 0）。目标字数默认 12,000 字。

## 9 给 AI 提意见 vs 自己改

| 你想做什么 | 用什么 |
| --- | --- |
| 这句话写得不好，重写这一条 | 条目卡「重生成」 |
| 方向不对，但我说不清具体怎么改 | 条目卡「提意见」，写一段你想怎么改 |
| 整个方向都要换（比如换主角动机） | 阶段级「给 AI 提意见」，范围选「整个阶段」 |
| 我就想自己改两个字 | 条目卡「编辑」 |
| 这条改对了，别再动它 | 条目卡「锁定」 |
| 想看这条被改过几次、改回上一版 | 条目卡「历史」 |

三条保护线：

1. **手改的东西不会被批量覆盖**：整阶段重生成会先列出「手改：…」「锁定：…」的清单，要你点「确认覆盖并重排」。
2. **锁定就是锁定**：锁定的条目在重生成时被跳过，不会出现在新内容里。
3. **历史永远可找回**：每次改动都记来源（AI 初稿 / 按意见重做 / 整份重生成 / 你修改 / 回滚 / 迁移），可以从历史恢复到任意一版。

## 10 旧作品怎么迁移

**没升级之前，旧作品照旧能用**：打开作品先进原编辑器（写作台 / 剧本页），什么都不变。顶部会有横幅：「这是升级前的旧作品。可以继续在原编辑器里写；也可以升级到 AI 流水线，正文、设定与历史版本都会保留。」

升级过程：

1. **点「升级到流水线」**。
2. **服务端先做预检**（数据完整性、字段、关系等若干项）。预检不过就**不升级**，返回「旧作品升级前的校验没通过——为了不弄坏原文，升级被挡住了」，旧作品仍可正常打开。
3. **升级在一个事务里做**：整库先备份，再搬数据。搬的规则只**新增**阶段 / 条目 / 单元行，**不改** `chapters.content`；已有正文、设定、历史版本原样保留。
4. **升级后自动校验**：与备份副本逐项比对（正文大小、哈希、各表计数）。任一项不一致就整体回滚，并把结果告诉你。
5. **可重入**：重复点升级不会搬两遍；中途失败可以直接重试。

**回退（升级后悔了）**：

- 横幅里给「回退到升级前」。
- 如果升级后你已经产生了新内容（新章节、新的版本、审阅记录、改动过的正文），回退会先弹确认并列出「会丢什么」，不会默默执行。
- 回退按「迁移时写入的行」精确清理，不会误删你升级后手改过的旧章。

**已知限制**：迁移账本（迁移前的章节清单）会随作品包（bundle）导出，但不出现在修订历史里。

## 11 出错的时候你会看到什么

AI 的失败一律变成「一句人话 + 一个出路」，不会静默失败，也不会假装成功。

### 11.1 配置类（最常见）

| 错误码 | 你看到什么 | 按钮 |
| --- | --- | --- |
| `NO_DEFAULT_MODEL` | 还没有选默认模型 — 到设置里挑一个供应商和模型，AI 才能开始工作 | 去设置里选模型 |
| `NO_API_KEY` | 这个供应商还没填 API Key | 去设置里填 Key |
| `AUTH_FAILED` | Key 无效或已经过期 | 去设置里更新 Key |
| `MODEL_NOT_FOUND` | 这个模型现在用不了 | 换一个模型 |
| `REASONING_UNSUPPORTED` | 这个模型不支持推理等级 | 去关掉推理等级 |
| `QUOTA_EXCEEDED` | 账户额度用完了 | 去设置里换模型 |

没有默认模型 / 没有 Key 时**作品根本不会创建**，也不会偷偷回退到「本地演示模型」——mock 只有你自己显式选中才会用。

### 11.2 运行时

| 错误码 | 你看到什么 | 按钮 |
| --- | --- | --- |
| `RATE_LIMIT` | 供应商限流了 — 通常 1–2 分钟就能恢复 | 重试 |
| `PROVIDER_TIMEOUT` | 模型服务超时 — 模型两分钟没返回内容 | 重试这一步 |
| `PROVIDER_ERROR` | 模型服务返回了错误 | 重试 |
| `EMPTY_OUTPUT` | 模型没有返回内容 | 重试这一步 |
| `INVALID_JSON` | 模型返回的格式不对 — 原始输出已保存 | 重试这一步 |
| `CONTENT_BLOCKED` | 内容被供应商拦截了 | 改一改再试 |
| `NETWORK` | 连不上本地服务 — 已经生成的进度都在本地 | 重试连接 |
| `CANCELLED` | 已取消 — 这一步被取消了，可以重新开始 | — |
| `INTERRUPTED` | 上次的生成被中断了 — 应用可能被关掉或崩溃过，已经写好的内容都在 | 从断点继续 |
| `STAGE_LOCKED` | 请先完成上一步 — 阶段要按「设定 → 大纲 → 章节计划 → 写作」的顺序推进 | — |
| `CONCURRENT_JOB` | 还有任务在跑 — 等当前任务结束，或者先暂停它 | — |

### 11.3 断网 / 刷新 / 崩溃

- **断网**：页面顶栏出现「与后台失去联系」。恢复后自动重连并刷新，不用手点。
- **刷新**：所有状态在服务端，刷新后回到原来的阶段与位置。
- **App 被关掉 / 崩溃**：下次打开时，正在跑的任务被标成「被中断」，顶部横幅给「从断点继续」；已经写完的章节逐字节不变。

## 12 常见问题

**Q：AI 会自己一路写完整本书吗？**
不会。每一章都要你审阅（通过 / 退回 / 人工通过 / 跳过）。「连续写」只是把「一章一章点开始」变成自动往下推，写完仍然等你审。

**Q：企划跑了很久，算失败吗？**
单步有 120 秒超时；超时会明确告诉你「模型服务超时」并给重试。界面上的进度每秒更新，不会出现「什么都没有、也不知道在不在跑」。

**Q：我不想用 AI 企划，只想自己写？**
新建时不勾「让 AI 先做企划」，或者预检不通过时点「仍然创建（只能自己写）」。旧作品的写作台也一直可用。

**Q：能改已经确认的设定吗？**
能。但改动会让下游阶段变成「上游有变更」/「待确认」，需要你再确认一次才会继续往下走——这是为了避免「设定改了、正文还按老设定写」。

**Q：为什么写了一章花了很久？**
正文是一章一次模型调用，长篇一章三五千字通常要几十秒到两分钟。控制条里有已用时；超时会明确报错。

**Q：我的数据在哪儿？**
全部在本机：`software/data/studio.db`（桌面版在 `~/Library/Application Support/Inkquay/data/studio.db`）。备份走「导出作品包」，不含 API Key。

## 13 本轮边界（v1 明确没做）

**设计上刻意不做**：

- 不做「一句话全自动出全书」：每个阶段都要人确认，每章都要人审。
- 正文不自动注入伏笔与人物关系（延续旧版语义，需要时在共笔面板手动引用）。
- 剧本 / 剧集不进流水线。

**能力缺口（已知，未做）**：

- 跨幕移动节拍（只能同幕内重排）。
- 章节行内「立即写本章」按钮未随「计划未确认」禁用（见 7.4）。
- P3 整阶段重生成，你确认覆盖后会把「目标字数」的按目标分配记录清零（已有正文 / 已锁定的章会被跳过不覆盖，历史可找回）。
- 写作页的详情请求没有单独超时（主快照请求有 15 秒上限）。

**没验证过的，就别当成已验证**：

- **只在本机 macOS（Apple Silicon）上验证过**，Windows / Linux 未跑。
- **真实供应商没有逐家验证**：主链路用的是本地假 OpenAI 兼容供应商 + 显式 mock（只在你自己选 mock 时才用）。历史审计阶段用真实 DeepSeek Key 手动重放过一次企划请求（200 / 190 ms / 返回 3108 字可解析），不代表其它 14 家都验过。
- **桌面安装包未签名、未公证**（macOS 自动更新会回退到下载页）；Windows / Linux 安装包未签名。
- **单进程假设**：同一份数据库只被一个进程用（没有分布式锁）。
- **迁移没有真实正样本**：安装版库里唯一的旧长篇作品本身就是之前那个空壳，验收用的是测试里现造的旧作品（临时数据目录，跑完即弃）。
