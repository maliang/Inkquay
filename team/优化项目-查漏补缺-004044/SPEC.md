## 总纲

**本轮不新增创作能力，只把已经承诺的能力变成真的能用**：让新用户进得来、让写下的字不丢、让按钮和它承诺的行为一致。
三条红线：**不丢数据、不假装成功、不留死路**。
凡是「界面上写着、代码里没有」的东西（假引文、假评分、假进度、无效开关、没实现的快捷键），本轮一律**要么做成真的，要么拿掉/标注「示意」**，不允许继续假装。

### 本轮最该优先做的 3 件事（结论先行）

1. **打通首启 + 对齐文案**（A-1）：它决定「新用户能不能看到产品」，也是唯一一个 100% 阻断的断点。
2. **堵住三条丢数据路径**：导出导航丢稿（A-3）、删库重启崩溃（A-2）、无备份（D-2/C-5）。数据丢了，后面所有优化都归零。
3. **清掉「假成功 / 假数据 / 无效开关」**（B-1/B-2/B-3）：这是用户说的「不人性化」的主体——按钮点了有反应但没效果，比没有按钮更伤信任。

### 本轮明确不做（防止范围蔓延）

- 不做账号 / 多用户 / 云同步 / 协作；不做遥测与联网上报。
- 不重写编辑器（仍是 `contentEditable`），不引入富文本库；格式（加粗/引用/列表）持久化列为**已知限制**，本轮只保证「不静默丢正文」，并在界面标注。
- 不做跨章节版本总览、撤销/重做、章节排序与分卷（待 D5）。
- 不做剧本 AI 生成（待 D5）。
- 不做 UI 视觉改版、不换设计系统、不重写 `prototype.css`（8132 行，仅做必要局部样式）。
- 不改 Electron 打包 / 签名 / 公证 / CI 发布流程（`desktop/`、`.github/` 不动）。
- 不动 `prototype/`（归档目录）。
- 不新增运行时依赖；如需新增必须用户确认（假设 H1）。

## 业务规则

> 每条写成「输入 → 输出/行为」；存量隐性规则显式化，拒绝一律带 HTTP 状态 + 中文 `error` 文案（前端 `request()` 会原样抛给 toast）。

| 规则 | 输入 | 输出 / 行为（含拒绝） |
|---|---|---|
| **R1 首启准入** | `POST /api/onboarding {name, providerId, modelId, apiKey?, baseUrl?}` | name 空 → 400「请填写称呼」；provider/model 缺失 → 400「请选择模型供应商和模型」；modelId 不在该供应商 models → 400「模型不存在」；非 mock/ollama 且无 key → 400「请填写 API Key」（若 D1 选口径 A，则新增 `providerId=mock` 时跳过 Key 校验并在响应里 `demo:true`）；成功 → settings.onboarding.completed=true，defaultModel 落库，返回设置 |
| **R2 新建章节** | `POST /api/projects/:id/chapters {title?, volume?, number?}` | 项目不存在 → 404「作品不存在」；title 空 → 默认「未命名章节」；number 空 → 默认「新章节」；`sort_order = max+1`；客户端负责取「现有最大章序号 + 1」作为 number；服务端**不因 number 重复而拒绝**（排序以 sort_order 为准），但前端必须防双击产生两条 |
| **R3 删除章节** | `DELETE /api/chapters/:id` | 不存在 → 404「章节不存在」；成功 → 200；级联：`chapter_versions`（FK CASCADE）、`ai_messages`（**无 FK，需显式 DELETE WHERE chapter_id=?**）；重算 `projects.total_words` 与 `updated_at`；删最后一章允许，前端显示空态 |
| **R4 删除人物 / 伏笔** | `DELETE /api/characters/:id`、`DELETE /api/foreshadows/:id` | 不存在 → 404「人物不存在」/「伏笔不存在」；成功 → 200；**不改写任何章节正文**；若人物在 beat/正文中被引用，只删实体（不级联删文本）；前端删除前确认 |
| **R5 删除场次 / 分镜** | `DELETE /api/scenes/:id`、`DELETE /api/shots/:id` | 不存在 → 404「场次不存在」/「分镜不存在」；删场次连带其 shots（FK CASCADE 已有）；场次号**不自动重排**（避免用户已引用编号） |
| **R6 删除供应商** | `DELETE /api/providers/:id` | `mock` → 400「本地演示模型不可删除」；被 `settings.defaultModel` 引用 → 400「该供应商是默认模型，请先在设置中切换」；被 `fallbackModel` 引用同理；成功 → 200 并从列表移除 |
| **R7 重新生成** | `POST /api/ai/stream {regenerate:true, messageId?}` | 未传 messageId → 以「该章最近一条 assistant」为目标；成功 → 覆盖目标消息内容（或旧条标记 `superseded=1` 且查询过滤）；**`ai_messages` 总数不变**；失败 → 不删旧消息，SSE 发 `{type:'error'}` |
| **R8 选区改写** | 前端 `sendPrompt` 附带 `selection{start,end,text}`；服务端 prompt | `selection.text` 长度 > 2000 字 → 400「选中文本过长，请分段改写」；替换时正文中找不到锚点 → 前端 toast「原文已变化，未写入」且**不修改正文、不打快照**；成功 → 精确替换该区间并打「改写前」快照 |
| **R9 导出** | `GET /api/projects/:id/export(.docx)` | 项目不存在 → 404「作品不存在」；生成异常 → 500 `{error:'导出失败'}`（不得返回半截文件）；文件名非法字符替换 `_`；无正文 → 仍导出封面并附「（本书尚无正文）」或前端提示；前端必须以 Blob 下载，不得用 `<a href>` 直链 |
| **R10 归档 / 取消归档** | `PATCH /api/projects/:id {status:'已归档'}` | 语义按 D4 定稿，两种实现都要求「取消归档可达」：若选 D4-A（隐藏+只读）→ 记录 `archived_from`（原状态）用于恢复、默认列表过滤、写接口 409「作品已归档，请先取消归档」；若选 D4-B（仅打标签）→ 保留可写，列表增加按状态筛选。未拍板前**不得**擅自让归档变成不可逆。 |
| **R11 设置写入** | `PUT /api/settings {partial}` | 未知字段忽略；已知字段浅合并（不整份覆盖）；枚举非法（theme/accent/aiLength）→ 400「设置项不合法」或回落默认并提示（二选一，实现前定）；`profile.name` 去首尾空格后为空 → 400「请填写称呼」 |
| **R12 版本快照** | `POST /api/chapters/:id/versions` | 章节不存在 → 404；与最新版 title+content 完全相同 → 不新增，返回旧版；每章保留最近 40 版，超出自动删最旧（UI 需标注） |
| **R13 版本恢复** | `POST /api/chapters/:id/versions/:versionId/restore` | versionId 不属于该 chapter → 404「版本不存在」（现有校验已按 `chapter_id` 过滤）；成功前自动打「回退前」快照；恢复后重算字数 |
| **R14 企划应用** | `POST /api/projects/:id/plan/apply {plan}` | `plan.acts`/`plan.characters` 非数组 → 400「企划数据不完整」；事务内：先快照第一章（`企划前`）→ 删旧 acts/beats/characters → 写新的；acts>4 或 beats>8/幕 或 characters>8 → 400「企划超出上限（最多 4 幕 / 每幕 8 个场景 / 8 个人物）」（当前是静默裁剪/未校验，需明确）；失败回滚，不留半套数据 |
| **R15 字数口径** | 任意正文写入 | 字数 = CJK 字符数 + 英文字母数字串数；**client 与 server 必须调用同一实现**（移到 `src/shared/`），编辑器显示与服务端 `words` 差 ≤ 0；`project.total_words` = 各章之和 |
| **R16 幂等与并发** | 重复提交 / 双击 | 同内容快照不新增（R12）；重复保存同一内容不产生新版本；双击新建章节只产生一条（前端 disabled + 服务端可接受但编号唯一）；并发同章 PATCH → last-write-wins，`updated_at` 取最后；不出现两条同 id 记录 |

## 边界与禁止项（强制 · 沉默 ≠ 允许）

> 每条必须是「禁止什么 → 期望拒绝（码/文案）→ 如何验收」。**没有拒绝码的边界视为未定义。**

| 边界族 | 规则（禁止什么） | 期望拒绝（码 / 文案） | 验收方式 |
|---|---|---|---|
| **自反关系** | 人物关系（relations）不得指向自己；同一条消息不得既作为 regenerate 的输入又被复制成第二条 | 400「不能关联自身」/ 忽略并保持原消息 | API 测试：`POST/PATCH` 传入 `characterId === targetId` |
| **归属 / 跨父级** | 用 B 项目的 chapterId/sceneId 调 A 项目的接口；`reorderBeats` 混入他项目的 beatId | 404「章节不存在」/「场次不存在」；reorder 混入 → 400「节拍不属于该作品」（现状是静默忽略，须改） | API 测试：跨项目 id 调用 |
| **终态不可变** | 已删除项目/子实体不可读写；已归档作品不可写（仅 D4-A 口径） | 404「作品不存在」/ 409「作品已归档，请先取消归档」 | API 测试 + Playwright |
| **越权** | 本地单用户：服务只监听 `127.0.0.1`；不得接受非本机来源的写请求；前端不得绕过 onboarding 守卫直达写接口 | 非本机来源 → 拒绝/不监听；未完成 onboarding 调 `POST /api/projects` → 400「请先完成初始化」 | API 测试（Host/Origin 头）+ 人工 |
| **幂等** | 双击「新建作品 / 新建章节 / 检查连接 / 导出」不得产生重复实体或重复下载 | 前端 disabled；服务端同内容不新增 | Playwright 双击 + API 计数 |
| **基数上限** | 版本 40/章；企划 acts ≤4、beats ≤8/幕、characters ≤8；以上为硬上限 | 超限 → 400「超出上限（最多 4 幕 / 每幕 8 个场景 / 8 个人物）」；版本超限 → 自动清理最旧（UI 标注） | API 测试构造超限 |
| **级联与计数** | 删除后不得残留孤儿；计数不得为负或与实际不符 | 删除 → 重算 `chapterCount` / `totalWords`；`ai_messages` 必须按 chapter 显式清理（无 FK）；孤儿数据不得被查询出来 | API 测试：删后查计数与消息 |
| **并发同键** | 两个并发保存同一章不得产生两条版本 / 两条消息 | last-write-wins；版本按内容去重 | 脚本并发 PATCH + 断言版本数 |
| **权限升降级** | 供应商被禁用/删除后，其模型不得再出现在模型菜单；默认模型失效时不得静默回落到 mock | 禁用 → 菜单移除；默认模型失效 → 400「默认模型不可用，请到设置中重新选择」（或明确提示后回落） | API + Playwright |
| **可见性** | 归档/软删对象的可见与可编辑边界必须一致；不得出现「列表可见但点开 404」或「已归档仍可 AI 续写」 | D4-A：默认列表隐藏、直达 409；D4-B：列表可见但标注且只读 | Playwright 两路径 |

## 边界 Case

- **空输入 / 非法输入**：标题为空（服务端按 R2 默认或 400）；标题超长（建议 ≤ 80 字，超出 400）；正文 >3MB → 413 且前端提示「章节过长，请拆分」；非字符串类型 → 400「参数不合法」；`NaN` 字数/进度（`goalWords=0`）→ 前端已 `Math.max(1,…)` 兜底，服务端不得除零。
- **权限边界**：未完成 onboarding → 所有页面重定向引导页（现状 `App.tsx:31` 已做，需保证 `/settings` 不被弹回造成死循环）；已完成但库被删/损坏 → 至少显示**可读原因**（区分「服务没起来」与「库读不了」）并给操作指引，不得只有「无法连接本地服务」。
- **并发 / 竞态**：800ms 自动保存与切章并发（切章必须**等待**保存完成或排队，不得 fire-and-forget 后立刻改状态为已保存）；双击新建；双击导出；流式中途切章（应 abort 并提示）。
- **历史脏数据 / 向前兼容**：旧 settings JSON 缺字段（现有浅合并已处理，需回归）；旧库无 `schema_version`（本轮加，旧库按 0 处理并原地升级）；未来新增列必须有默认值；`data/studio.db` 可由用户手工替换（备份恢复路径）。

## 安全边界（三级权限）

- **必须做**：
  1. API Key 仍用 AES-256-GCM 加密存储；接口只回 `apiKeyMasked`（尾 4 位），任何日志/错误/导出设置中不得出现明文 Key。
  2. 服务只监听 `127.0.0.1`；不引入 CORS 通配；`express.json({limit:'3mb'})` 保持。
  3. 所有新接口做「存在性 + 归属」双校验（404 优先，避免跨项目探测）。
  4. 删除类操作前端必须有确认；服务端删除不可逆操作需在响应里带 `deleted:true` 供前端展示。
  5. 导出/备份路径不得由用户输入拼接（禁止路径遍历）。
- **先询问**（抛给用户拍板，不得自行决定）：
  1. 是否允许局域网/远程访问（会影响绑定地址与鉴权设计）；
  2. 是否引入云同步/备份到云端；
  3. 是否上报匿名使用统计（默认不做）；
  4. 备份文件是否包含加密后的 Key（默认包含，因为恢复需要；若要脱敏则恢复后需重填 Key）。
- **严禁做**：
  1. 删除或重置用户 `data/` 目录、`studio.db`（任何「修复」脚本都不得静默删库）。
  2. 改加密算法/密钥派生导致旧 Key 无法解密（如需改，必须提供再加密迁移）。
  3. 把 `apiKey` 写进日志、错误响应、导出 JSON、前端 localStorage。
  4. 为了「让流程走得通」而移除 onboarding 守卫或绕过归属校验。
  5. 不可逆删除**没有确认步骤**（`window.confirm` 或自定义确认弹窗均可，但必须有）。
  6. 引入会修改用户正文的自动操作（如自动改写、自动删除空章）。

## 必须由用户拍板的 5 个产品决策

> 按 POLICY：**不代决策**。以下每项给出选项、推荐与影响；未拍板前实现方按「推荐」写，但需在 `DECISIONS.md` 留痕。

### D1｜首次启动准入：没有 API Key 的用户怎么进书房？

| 选项 | 说明 | 影响 |
|---|---|---|
| **A（推荐）** | onboarding 增加「本地演示模型（mock）」选项，选它可跳过 Key 校验直接进入；空态文案与之一致 | 门槛最低、与现有文案一致；缺点是 mock 输出质量低，用户可能误判 AI 能力 → 需在界面显著标注「演示模型，仅供体验」 |
| B | 继续强制真实 Key，但把文案改成「需要至少一个可用模型才能进入」，并在引导页给申请 Key 的链接 | 真实体验最好、改动最小；缺点是没 Key 的用户永远看不到产品，与「本地优先、开箱即用」定位冲突 |
| C | 允许「先跳过，稍后配置」进入书房，只禁用 AI 相关按钮 | 最灵活；代价是所有 AI 入口都要做「未配置」空态与引导，验收面变大 |

### D2｜删除与恢复：误删之后能不能救回来？

| 选项 | 说明 | 影响 |
|---|---|---|
| **A（推荐）** | 硬删除 + 二次确认 + 删除前自动快照（章节/作品层），不引入回收站 | 改动小、符合本地单用户习惯；删除即不可恢复（章节版本快照可救正文，但人物/伏笔不可救） |
| B | 软删除（`deleted_at`）+ 回收站，30 天后清理 | 最安全；但要给所有查询加过滤、给列表加回收站页，改动面最大（repository 全链路） |
| C | 只补「章节删除」，其余实体暂不提供删除 | 范围最小；但人物/伏笔/场次删不掉的问题仍在，用户仍会骂 |

### D3｜导出与备份：损失多大算可接受？

| 选项 | 说明 | 影响 |
|---|---|---|
| **A（推荐）** | 只做「备份数据库文件（下载 studio.db 副本）」+ 修导出交互（loading/失败/空稿提示）+ 文案说明「恢复=替换 data/studio.db」 | 成本低，覆盖 90% 的「怕丢」诉求；恢复需要用户手动放文件 |
| B | A + 全量 JSON 导入/导出（含作品、章节、人物、设置，不含明文 Key） | 可迁移、可跨机器；需要定义 schema 版本与冲突策略，工作量中 |
| C | 只修导出交互，不做备份 | 最省；但「本地应用」最大的恐惧（硬盘坏了/换电脑）没有答案 |

### D4｜归档：它到底意味着什么？

| 选项 | 说明 | 影响 |
|---|---|---|
| **A（推荐）** | 归档=从默认列表隐藏 + 只读 + 可取消归档（记忆归档前状态） | 语义清晰；需加状态筛选与写接口 409 校验 |
| B | 归档=只打标签（维持现状），补「按状态筛选」 | 最省事；但「归档」这个词仍然名不副实 |
| C | 移除「已归档」选项，改为「完结」状态 | 简化认知；但删掉一个已有功能，需确认没有用户在用 |

### D5｜本轮范围：AI 能力做到哪一步？

| 选项 | 说明 | 影响 |
|---|---|---|
| **A（推荐）** | 只修已有 AI 流程的正确性（regenerate 去重、插入位置、改写定位、设置项生效、失败提示），不做新 AI 能力 | 范围可控、可用 mock 验证；剧本项目仍无 AI 企划 |
| B | A + 剧本 AI 企划/场次生成 | 补齐剧本链路；但需要真实 Key 验证质量，验收面显著变大 |
| C | A + 跨章节版本总览 + 单章导出 | 长篇小说作者刚需；但版本模型要跨章聚合，工作量中偏大 |
