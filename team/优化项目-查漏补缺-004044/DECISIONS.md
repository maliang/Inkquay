## D1 · Onboarding 准入 **[已确认，本轮不推翻]**

- **选了什么**：保持「首次启动强制填写 API Key，不填不能进主界面」；**不新增**跳过/匿名/免 Key 模式。本轮只修「文案与实现互相打脸」：
  - `LibraryPage.tsx:111-119` 写「默认本地演示模型，不需要 Key」← 与 `OnboardingPage.tsx:11`（过滤 mock）、`App.tsx:31`（全局拦截）矛盾 → 改为「首次需要连接一个模型供应商并填入 API Key」。
  - `SettingsPage.tsx:286/294` 同类承诺 → 删除或改写为「内置演示模型仅用于体验，不能作为首次配置」。

- **备选 A**：允许 mock 完成 onboarding（SPEC 曾倾向此方案）→ **不选**：用户口径已明确保持强制准入，且放开会让「作品在别人机器上打不开模型」的困惑变成常态。
- **备选 B**：加「我先看看」只读模式 → **不选**：等于新增一条产品路径，超出「修流程不通」的范围。
- **影响面**：`LibraryPage.tsx`、`OnboardingPage.tsx`、`SettingsPage.tsx` 三处文案 + 一个错误提示（T31）。
- **待用户确认**：文案统一口径是否就用这句——
  > 「首次进入需要连接一个模型供应商并填入 API Key；内置演示模型仅用于体验，不能作为首次配置。」

## D2 · 删除策略 **[部分待确认：章节「删除前快照」技术上不可直接成立]**

- **选了什么**：不做回收站、不做软删除。硬删除 + 强确认：
  - 章节：弹窗展示「字数 / 首段 100 字 / **该章 N 条历史版本将一并删除**」，并要求输入章节标题末两个字才启用删除按钮。
  - 人物/伏笔/分镜：普通二次确认；场次：提示「连带删除 N 条分镜」。
  - 全部删除走 404 优先的归属校验；`deleteChapter` 在事务内显式删 `ai_messages`、重算 `total_words`，`chapter_versions` 由 FK CASCADE 处理。
- **必须说清的技术事实**：用户建议的「章节删除前自动生成版本快照」在当前 schema 下**无法保留**——`chapter_versions.chapter_id TEXT NOT NULL REFERENCES chapters(id) ON DELETE CASCADE`，快照会随章节一起被删。
- **备选 A（本轮不选）**：把 `chapter_versions.chapter_id` 改为可空 + 加 `deleted_at`，删除时留「孤儿快照」，并在版本面板加「已删除章节」入口 → 需要重建表（SQLite 不能 ALTER 掉 NOT NULL）+ 新增列表/恢复 UI，**实质就是半个回收站**，与「不做回收站」和「避免大重构」两条同时冲突。
- **备选 B（本轮采用，兜底）**：删除前**不做自动快照**，改为①确认弹窗明确「历史版本一并删除」②引导用户先「立即备份」（同一页有入口）③删除后 toast 提供「去备份页」。
- **备选 C**：把章节内容复制成一条「项目级备份消息」塞进 `ai_messages` → 语义污染（AI 对话里出现正文），不选。
- **待用户确认**：接受备选 B（硬删 + 强确认 + 明示版本一并删除），还是愿意为备选 A 多付约 0.5–1 人日 + 一次表重建（我会拆成独立 T，不进 P0/P1 关键路径）？

## D3 · 备份 / 恢复 / 导入 **[待确认：密钥与二期范围]**

- **选了什么**：做**完整本地备份/恢复**（用户口径）：
  - `GET /api/backup` → 单个 `.json`，含 12 张表全部行 + `app.version` + `secrets.keyBase64`（`.secret` 原文）；响应头 `X-Backup-Contains-Secrets: 1`；下载前弹窗提示「此文件包含可解密 API Key 的密钥，请勿上传公开网盘」。
  - `POST /api/restore` → 校验 `format/formatVersion` → **自动把当前 `studio.db` 与 `.secret` 复制到 `data/backups/pre-restore-<ts>.*`** → 事务内清表重灌 → 可选恢复 `.secret` → 返回 counts 与备份路径 → 前端 `location.reload()`。
  - 恢复前二次确认要求输入「恢复」二字；已有非空库时需 `?force=1`。
  - 同时修导出（见 D-导出，PLAN §6 T19/T20）。
  - **单作品 JSON 导入/导出（bundle）本轮不做**，列二期。
- **备选 A**：只备份 `studio.db` 文件（SPEC 倾向）→ **不选**：文件与 `.secret` 分离，换机后 Key 全解不开，用户会以为「备份坏了」；且无法在浏览器里触发（桌面端还要暴露文件系统）。
- **备选 B**：只做 bundle（项目级 JSON），不做整库 → **不选**：user 明确要「完整本地备份/恢复」，且 bundle 丢设置/供应商/消息；leadv1 草案的 bundle 方案降为二期。
- **备选 C**：备份默认不含密钥（更安全）→ **不选（但保留勾选）**：不含密钥时「恢复后所有 Key 需重填」，对单机用户是负体验；默认包含 + 明确警告 + 可选剔除，是安全与可用的折中。
- **待用户确认**：
  1. 备份默认**包含**加密密钥（推荐，跨机可完整恢复），还是默认**不含**（更安全，恢复后需重填 Key）？
  2. 恢复后是否要求**重启应用**（服务端建议只 reload；若你希望更保险，我可让桌面端在恢复后自动重启子进程，+1 任务）。

## D4 · 归档 **[已确认：不做只读大改，只补可见性与撤销]**

- **选了什么**：归档仍是 `projects.status='已归档'`（无 `archived` 列，不新增列）：
  - 作品库默认显示「创作中 + 已完结」，新增「显示已归档」开关（localStorage 持久化），已归档卡片打灰标。
  - 作品设置里当 `status==='已归档'` 时按钮变「取消归档」（写回 `创作中`）。
  - 归档动作的 toast 增加「可在作品库勾选『显示已归档』找回」。
- **备选 A**：归档=只读（禁止 AI 续写/禁止编辑）→ **不选**：需要贯穿 `PATCH /api/chapters`、`POST /api/ai/stream`、`applyPlan` 等全部写入路径的状态校验，还会让「临时归档又继续写」变得别扭；收益低。
- **备选 B**：归档=彻底隐藏（不出现在任何列表）→ **不选**：就是当前 bug 的成因（RESEARCH 已证实「归档作品不会消失，只是没筛选」，但用户感知是「不见了」）。
- **待用户确认**：写作台/大纲页打开已归档作品时，是否加一条只读样式的横幅「此作品已归档」+「取消归档」按钮（不做写入限制）？

## D5 · AI 能力 **[已确认：只修正确性/可取消/可恢复/上下文污染]**

- **选了什么**：
  - 可恢复：abort/error 且已产出文本 → 落库 `status='aborted'`，UI 显示「已中止」卡片（插入/重试/丢弃）。
  - 可取消：`plan` 请求可 abort（`res.on('close')`）+ 100s 超时 504；客户端 `AbortController`。
  - 正确性：`regenerate` 用 `regenerateOf` 替换目标消息（总数不变）；选区改写按偏移定位；插入/替换保原生撤销；分镜可强制重新生成。
  - 上下文污染：`listMessages` 严格按章；`buildWritingContext` 注入 `prefs.pov/genre/aiLength/style`（这些设置此前完全没被使用，属于「假开关」）。
  - 不新增：不做新 prompt 玩法、不做多轮 agent、不做自动润色全章。
- **备选 A**：把 regenerate 改成「新增一条并标记 superseded」→ **不选**：消息表要多一列且查询更绕；直接替换更简单，且用户预期就是「重写这条」。
- **备选 B**：`fallbackModel` 做多级重试 → **不选（降级为单次）**：多级重试会让「为什么这条回复风格变了」难以解释；只做「首个 delta 前失败 → 备用一次」，仍超预期则从 UI 移除该项。
- **待用户确认**：`fallbackModel` 若实现成本超 2 小时，是否同意直接**从设置页移除**（而不是留一个不生效的开关）？

## D-导出 · 导出策略 **[待确认：范围选项]**

- **选了什么**：`fetch`+`Blob` 下载；范围可选 `整本 / 当前卷 / 当前章`；空正文返回 400 可读错误并在前端 toast；`<a href>` 全部替换（`StudioPage:443-444`、`ScreenplayPage:137-138`）。
- **备选**：只修错误处理、不加范围选择 → **不选**：SPEC A5/A6 与 RESEARCH P1-10 都点了「无当前章导出」「空项目 77 字节」，范围选择是最低成本的可用性提升。
- **待用户确认**：范围选项是否需要「当前章」之外的「选中章节多选」？（建议不做，多选 UI 成本高于收益）

## 实施期最终口径（2026-10-27，覆盖上文待确认项）

- **范围**：用户拍板方案 A（P0 + P1 日常体验），不做整库恢复、不重写编辑器、不引入新运行时依赖。
- **首启准入**：保留强制 onboarding（称呼 + 云 API Key）；mock 不作为免 Key 入口，仅修文案与检查连接提示。
- **备份**：采用**项目 JSON bundle**；含章节、版本历史、大纲、人物、场次、分镜、伏笔；**不含 `.secret` API Key**，不提供整库恢复。原 D3“整库 + `.secret`”方案未实施，bundle 从二期提前到本轮。
- **章节删除**：硬删 + 明确提示“历史版本一并删除”；不做软删/回收站，也不承诺快照可恢复（`chapter_versions` 对 `chapters` 是 `ON DELETE CASCADE`）。
- **假开关**：备用模型、流式输出开关、`G L` 快捷键未实现，已从 UI 移除；写作视角/文风/目标字数/默认题材改为真实注入或真实预选。
- **归档**：D4 归档可见性/只读横幅未纳入方案 A，保持现状，列后续。
- **fallbackModel**：保留数据字段兼容旧设置，但 UI 不再暴露；不实现自动回退。
